# 🎮 Neon Platformer - 엔진 아키텍처 및 멀티플레이 가이드

이 문서는 **Neon Platformer**의 기술 스택, 자체 엔진 아키텍처, 서버 비용이 발생하지 않는 원리, 그리고 WebRTC P2P 기반 멀티플레이 동작 원리를 정리한 개발 문서입니다.

---

## 1. 프레임워크 및 기술 스택 (Tech Stack)

본 게임은 Phaser, Pixi.js, Unity 같은 외부 게임 엔진이나 무거운 웹 프레임워크를 일절 사용하지 않고, **순수 바닐라 자바스크립트(Vanilla JS)**와 **HTML5 표준 API**만으로 밑바닥부터 직접 구축한 **자체 제작 2D 게임 엔진**입니다.

* **프로그래밍 언어:** Vanilla JavaScript (ES6+ Class 구조)
* **그래픽 및 렌더링:** HTML5 Canvas 2D API (`CanvasRenderingContext2D`)
* **물리 및 충돌:** AABB 박스 충돌 & 45도/경사로(Slope) 수학 충돌 직접 구현
* **사운드 시스템:** Web Audio API & HTML5 Audio
* **멀티플레이/네트워크:** PeerJS (WebRTC DataChannel P2P)
* **호스팅:** Vercel (정적 웹 호스팅)

---

## 2. 서버 요금이 0원인 이유 (비용 구조)

게임 서비스나 개발 과정에서 **어떤 서버 비용도 청구되지 않습니다 (완전 무료).**

1. **순수 클라이언트 실행:**
   * 게임 로직, 그래픽 렌더링, 물리 연산, 사운드 처리가 100% 플레이어의 브라우저에서 수행됩니다.
   * 백엔드 API 서버나 별도의 데이터베이스(DB) 인스턴스를 유지할 필요가 없습니다.
2. **정적 파일 호스팅 (Vercel):**
   * Vercel은 정적 파일(`index.html`, `js`, `png`, `mp3` 등)만을 배포하는 CDN 역할을 수행하며, 개인 프로젝트 기준 무료 티어로 충분히 운영됩니다.
3. **P2P 통신:**
   * 멀티플레이 시 플레이어 간 게임 패킷이 중앙 서버를 경유하지 않고 직접 전송되므로 트래픽 비용이 발생하지 않습니다.

## 3. WebRTC P2P & Vercel 멀티플레이 원리

> **Q. Vercel로 프론트엔드 파일만 올렸는데, 백엔드 서버 없이 어떻게 멀티플레이가 될까요?**

### 3-1. 핵심: PeerJS 무료 공개 시그널링 서버
WebRTC는 브라우저 간 1:1 직접 연결이지만, **처음 서로의 IP와 접속 주소(명함)를 교환하기 위한 중개인(Signaling Server)**이 딱 한 번 필요합니다.
* 본 프로젝트는 `new Peer()`를 생성할 때 **PeerJS 재단이 전 세계에 무료로 개방한 공개 시그널링 서버 (`0.peerjs.com`)**를 이용합니다.
* 따라서 개발자가 직접 Node.js/소켓 서버를 띄우지 않아도 방 생성 및 친구 초대가 가능합니다.

### 3-2. 연결 및 데이터 전송 흐름

```text
1. 파일 다운로드 (Vercel)
   [ Vercel CDN ] ───(HTML / JS / Asset 다운로드)───> [ 유저 A, B ]

2. 접속 주소 교환 (PeerJS 무료 시그널링 서버)
   [ 유저 A (호스트) ] ───(방 생성: 룸 코드 발급)───> [ PeerJS 공개 서버 ]
   [ 유저 B (게스트) ] ───(룸 코드로 A 주소 조회)───> [ PeerJS 공개 서버 ]
                              │
               (서로의 네트워크 주소(SDP/ICE) 전달)
                              ▼

3. 실시간 게임 플레이 (브라우저 간 직접 연결, P2P DataChannel)
   [ 유저 A 브라우저 ] ◄═══════ (초당 60회 동기화) ═══════► [ 유저 B 브라우저 ]
                        • 캐릭터 좌표 (X, Y)
                        • 스프라이트 모션 및 방향
                        • 팔레트 색상 번호
                        • 인게임 실시간 채팅
```

* **악수가 끝난 후:** 시그널링 서버와의 연결은 끝나며, 게임 도중 발생하는 대량의 패킷(좌표, 모션, 채팅)은 **두 사람의 PC 사이에서만 광속으로 직접 왕복**합니다.

## 4. 인게임 멀티플레이 이용 방법

### 4-1. 온라인 컴퓨터 위치
* 첫 번째 맵(`tutorial_1`) 시작 지점에서 옷장(팔레트 드레서) 바로 오른쪽에 **컴퓨터 오브젝트 (`OnlineComputer`)**가 배치되어 있습니다.
* 컴퓨터 앞에 서서 머리 위에 `PRESS UP`이 뜨면 **`위 방향키(↑)`**를 눌러 온라인 메뉴를 엽니다.

### 4-2. 방 만들기 (호스트)
1. 메뉴에서 `CREATE` 선택 ➔ `CREATE SVR` 선택
2. 프롬프트 창에 원하는 룸 코드(예: `apple123`)를 입력하거나 빈칸으로 확인을 누르면 임의의 코드가 생성됩니다.
3. 발급된 **룸 코드(Peer ID)**를 복사하여 친구에게 메신저나 디스코드 등으로 공유합니다.

### 4-3. 방 들어가기 (게스트)
1. 친구도 게임에 접속하여 컴퓨터 앞에서 **`위 방향키(↑)`**를 누릅니다.
2. 메뉴에서 `JOIN` 선택 ➔ `JOIN SVR` 선택
3. 호스트에게 전달받은 **룸 코드를 붙여넣고 확인**을 누르면 즉시 동기화되어 친구 캐릭터가 화면에 나타납니다.

### 4-4. 지원 기능
* **실시간 물리/스프라이트 동기화:** 친구의 이동, 대시, 마하 달리기, 벽타기, 슈퍼점프, 찍기(Groundpound) 등 모든 액션 반영
* **커스텀 팔레트 및 닉네임:** 상대방이 설정한 스킨 색상과 머리 위 닉네임 실시간 표시
* **인게임 채팅:** 게임 플레이 중 **`Enter`** 키를 누르면 화면 좌측 하단에 채팅창이 활성화되어 실시간 대화 가능
